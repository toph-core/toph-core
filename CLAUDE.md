This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Mary AI POS — a Flutter **kiosk application for restaurants/cafes** (Windows desktop is the primary target; macOS/Linux also run). Features: settings, menu management, shifts, halls & tables (tables are either `simple` — pay for food only — or `time_based` — hourly price via a table timer), receipt printing to ESC/POS thermal printers, and multiple staff roles (admin, cashier, waiter). UI text and code comments are largely in **Uzbek**; keep that convention in comments.

## Commands

```bash
flutter pub get                        # deps
dart run build_runner build --delete-conflicting-outputs   # freezed / json_serializable / hive codegen
flutter pub run intl_utils:generate    # regenerate l10n AFTER editing lib/l10n/*.arb
flutter analyze                        # lint (flutter_lints + overrides in analysis_options.yaml)
flutter test                           # all tests
flutter test test/global_virtual_keyboard_test.dart   # single test file
flutter run -d windows                 # run (or -d macos)
flutter build windows --release        # release build (CI: .github/workflows/build-windows.yml, pinned to windows-2022)
```

**l10n is generated by `intl_utils`, NOT `flutter gen-l10n`** — there is no `l10n.yaml`; config is the `flutter_intl:` block in pubspec.yaml. ARB files: `lib/l10n/intl_{en,uz,ru}.arb` (keep the three key-sets identical). Generated class `S` in `lib/generated/l10n.dart`; usage pattern `S.current.strXxx` (keys prefixed `str`, camelCase; `{placeholder}` in an ARB value auto-generates a method). Regeneration does NOT run automatically — run the command after every ARB edit. Never hand-edit `lib/generated/`.

## Architecture

### Entry & app shell
`lib/main.dart`: single-instance guard (loopback TCP lock on port 45671 — second launch focuses the existing window), `window_manager` setup, Hive init, then DI init. Root `MultiBlocProvider` provides app-wide cubits (`AuthCubit`, `SettingsCubit`, `MainCubit`, `ConnectivityCubit`, …). `MaterialApp` rebuilds on `SettingsCubit.state.language` (`'uz'`/`'ru'`, default `'ru'`; locales en/uz/ru). Routing is classic named routes: `lib/core/routes/app_routes.dart` + `app_pages.dart`, initial route = splash → PIN login. `AppScaffold` (`lib/core/widgets/app_scaffold.dart`) wraps screens with sidebar + `GlobalVirtualKeyboard`.

### Layers & DI
- DI: `get_it` in `lib/di.dart`; resolve with `inject<T>()`.
- State: `flutter_bloc` (blocs & cubits), `freezed` states/models. Feature blocs live in `features/view/<feature>/presentation/cubit/`.
- Feature layout: `lib/features/view/{auth,main,cashier,order}/` with `data/models`, `domain/{entities,usecase,pricing}`, `presentation/{cubit,pages}`. The `main` feature holds most POS screens: `detail/` (order screen for a table), `payment/`, `main/` (halls & tables map), `waiter/`, `menu/`, `settings/`, `archive/`, `close_shift/`, `notification/`. `features/view/cashier/` appears to be orphaned legacy (no route references) — verify before investing work there.

### Networking
`DioClient` (`lib/core/api/dio_client.dart`) with interceptors, in order: `_OfflineInterceptor` (offline queue for writes; `ConnectivityCubit` gates everything — no error toasts while offline), `MySmartDioInterceptor` (`dio_interceptor.dart`: Bearer token + single-flight refresh on 401 → logout on failure; sends `Language` header; on 4xx/5xx shows a localized fallback toast via `api_error_overlay.dart`/`flush_bars.dart`), Alice inspector, PrettyDioLogger. Endpoints are centralized in `lib/core/api/list_api.dart`. `userFriendlyDioError()` in `api_error_overlay.dart` is the canonical Dio-error→localized-message helper — reuse it, don't reinvent.

### Tables & the time-based timer (core domain)
- The timer belongs to the **order**, not the table: `/api/v1/orders/{orderId}/table-timer` (+ `/start`, `/pause`, `/resume`). `TableTimerCubit` syncs with the server every 60s and ticks the UI locally every 1s while `running`.
- Pricing is strategy-based: `TablePricingResolver` (`lib/features/view/main/domain/pricing/table_pricing_strategy.dart`) picks `SimpleTablePricing`, `TimeBasedAccruingPricing` (live `elapsed × price_per_hour`), or `FrozenTimePricing` (timer `closed` with `final_amount`, e.g. after transfer to a simple table).
- Table transfer (`POST /orders/{id}/transfer`) keeps the order and its accumulated time; the backend returns the **new** table's `price_per_hour`, so the client just re-renders `total_active_sec × price_per_hour`.
- The order actions bar (detail screen) shows **food + timer only**; the **service amount is added only on the payment screen** (`PaymentBloc.effectiveTotal` computes food+service from the freshly loaded detail; the `service_percent` route arg is only a display fallback). Do not re-add service to the bar.

### Printing
ESC/POS via `esc_pos_utils_plus`. `PrinterService` (`lib/core/service/printer/`) resolves a per-role `PrinterConfig` (`getCloseCheckPrinter()` for cashier/shift receipts, `categoryPrinterForOrNull()` for kitchen): `connection_type: 'cable'` → Windows printer API (IP ignored); `wlan`/LAN → raw TCP to `ip:9100`. Printer settings are saved to the backend (`/settings/printer-settings`) but **printing reads a local SharedPreferences cache** (`PrinterConfigStorage`), refreshed on login (`UserBloc` → `SyncPrinterSettingsUsecase`) and whenever the Settings → Printers section loads — keep both sides in sync when touching this flow. Receipt byte-builders live in `core/service/printer/receipt/` (`cashier_receipt_builder.dart`, `kitchen_receipt_builder.dart`, `shift_close_receipt_builder.dart`). **Known pitfall:** the payment screen's `ReceiptPreviewModal` re-implements receipt layout in widgets and has drifted from `CashierReceiptBuilder.buildFromDetail` (discount math, cancelled-item filtering, cashier-name source) — when touching either, keep them in sync or share the computation.

### On-screen keyboard (kiosk)
`GlobalVirtualKeyboard` (`lib/core/widgets/global_virtual_keyboard.dart`) is mounted app-wide by `AppScaffold`; the detail screen and some dialogs embed their own inline `VirtualKeyboard` instances. Layouts (Latin QWERTY + Russian ЙЦУКЕН) come from `AppKeyboardLayoutKeys` (`app_keyboard_layouts.dart`), defaulting from the app language. Two hard-won rules: (1) the layout object must be a **stable** field (`late final`) — recreating it per build resets the language on every rebuild; (2) the globe key's full-cell tap is handled in `postKeyPress` (`SwithLanguage` action) because the package's own handler only covers the icon pixels.

### Localization status
A sweep to replace hardcoded strings with `S.current` keys is in progress (~450–650 strings remain across waiter/settings/main/menu/archive/payment/printer-receipts). Phase 1 (dio_interceptor fallbacks, order-status label getters in `open_order_model.dart`/`order_line_item_model.dart`, `table_timer_section.dart`) is done. When adding UI text, always add ARB keys (all 3 files) — never hardcode. Note `lib/core/utils/order_localizations.dart` is a legacy ARB-independent uz/ru map, pending consolidation.

## Working style (from docs/claude.md)

Be concise and production-minded; prefer code over prose; choose the simplest robust approach rather than listing alternatives. Assume real-world POS constraints: flaky networks, multiple printers (cashier/kitchen separation), retry/fallback for printing. `docs/` holds design/session notes (`design_system.md`, `table_timer.md`, `api-flows-backend.md`, `WINDOWS_BUILD_FLOW.md`).
